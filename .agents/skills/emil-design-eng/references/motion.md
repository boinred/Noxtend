# 모션 기본 권고와 예외

모션 선택·리뷰·감사의 공통 판단 자료다. 아래 수치는 시작점이며, Noxtend의 제품 정책과 [DESIGN.md](../../../../DESIGN.md)의 토큰을 우선한다. 다른 모션 스킬에 같은 수치 표를 복제하지 않는다.

## 필요성과 빈도

| 사용 맥락 | 기본 권고 | 예외 판단 |
| --- | --- | --- |
| 빠르게 반복하는 단축키·탐색·command palette | 이동 효과 생략 또는 최소화 | 짧은 상태 피드백이 이해를 돕고 다음 입력을 지연시키지 않는 경우 |
| 자주 쓰는 hover·toggle·목록 조작 | 작고 짧은 피드백 | 현재 상태를 혼동하지 않도록 추가 설명이 필요한 경우 |
| 가끔 여는 modal·drawer·toast | 필요한 공간 관계와 상태 변화 표현 | 이미 정적 표현이 충분하면 모션 생략 |
| 드문 onboarding·완료 순간 | 제품 목적에 맞는 선택적 강조 | 실제 작업 상태·접근성 정책과 충돌하지 않는 경우 |

키보드 입력 자체를 금지 사유로 사용하거나 이용 횟수를 임의로 추정하지 않는다. 실제 목적·반복 빈도·반응 지연으로 판단한다. 장식 효과는 조작 가능 시점을 늦추지 않는다.

## Easing

- 진입·종료와 즉각적인 응답에는 `ease-out`, 화면 안의 위치 변경에는 `ease-in-out`, 작은 색상 변화에는 `ease`를 시작점으로 사용한다.
- `linear`는 일정한 진행·회전에 적합하다. `ease-in`은 초기 반응을 늦출 수 있으므로 종료 효과나 의도된 가속에서 목적을 확인한다.
- 기존 easing 토큰을 우선한다. built-in easing이라는 이유만으로 교체하거나 새 cubic-bezier를 만들지 않는다.

## Duration

| 요소 | 일반적인 시작 범위 |
| --- | --- |
| 눌림 피드백 | 100–160ms |
| tooltip·작은 popover | 125–200ms |
| dropdown·select | 150–250ms |
| modal·drawer | 200–300ms |
| 큰 표면 이동·설명용 효과 | 목적에 따라 더 길게, 이유와 확인 방법 명시 |

300ms는 빠른 UI 반응의 기본 목표다. 큰 drawer에서 300–500ms를 선택할 수 있지만 입력 지연·빠른 재입력·reduced motion을 확인한다. hold-to-confirm의 진행 시간은 일반 UI 전환 시간과 구분한다.

## 중단과 spring

- 고정된 단순 효과는 CSS transition을 우선한다. 재입력이 있는 전환은 현재 표시 상태에서 방향을 바꿀 수 있어야 한다.
- keyframe은 반복·정해진 연출에 유용하다. 빠른 재시작에서 점프가 재현되면 transition 또는 기존 spring으로 단순화한다.
- drag·관성·속도 인계에는 기존 spring API를 검토한다. 라이브러리가 이미 있을 때 `bounce: 0`, 짧은 반응으로 시작하고 물리적인 이유가 있을 때만 bounce를 늘린다.
- `duration`·`bounce` 방식과 `mass`·`stiffness`·`damping` 방식의 의미는 설치된 라이브러리 API로 확인한다. 서로 다른 spring 모델의 수치를 일대일 대응으로 단정하지 않는다.
- pointer 추적을 부드럽게 만드는 장식 spring이 실제 slider나 좌표 조작을 늦추지 않게 한다.

## Origin·scale·stagger

- 트리거에 연결된 표면은 트리거 방향에서 전환하고 중앙 modal은 중앙을 유지한다.
- scale 진입은 `0.9–0.97` + opacity를 시작점으로 한다. `scale(0)`이나 단순 fade는 목적과 실제 결과로 판단하며 코드 표현만으로 차단하지 않는다.
- 목록 stagger는 선택적인 강조다. 사용할 경우 항목 간 30–80ms로 시작하고, 큰 목록에서는 총 지연을 줄이거나 제거한다.
- hold 진행과 완료 응답은 다른 시간을 가질 수 있다. 일반 enter/exit가 같은 시간이라는 이유로 비대칭을 강제하지 않는다.

## 판단과 검증

- 코드 위치·재현 조건·사용자 영향을 확인한 문제와 기본 권고·취향을 구분한다.
- 빠른 반복 입력, 닫힘 중 재열기, 포커스 이동, reduced motion을 확인한다. 느낌을 확인하기 어렵다면 미확인으로 보고한다.
- 느린 재생·프레임 단위 관찰은 origin·겹침·타이밍 확인에 사용한다. 실제 반응성과 성능은 정상 속도에서도 확인한다.
- 성능과 접근성 판단이 필요하면 [performance-accessibility.md](performance-accessibility.md)를 읽는다.
