# 영역별 코드 지도

이 폴더는 AI 에이전트(Codex, Claude Code)가 Noxtend를 수정할 때 읽는 영역별 코드 지도다. 시작점은 [CODEMAP.md](CODEMAP.md)이며 작업별 지도 선택표도 그곳에 있다. 공통 작업 규칙은 루트 [AGENTS.md](../../AGENTS.md), 영역별 규칙은 각 영역의 `AGENTS.md`를 따르고 이 폴더는 그 지침을 복제하거나 대체하지 않는다.

## 에이전트 작업 규칙

- 루트·영역 `AGENTS.md`, 이 폴더의 `CODEMAP.md`와 작업에 해당하는 지도만 읽는다. 이 폴더의 모든 문서를 무조건 읽지 않는다.
- 현재 동작은 코드·테스트·실행 설정으로 확인한다. README, 과거 Plan·Design, migration 이름만으로 구현 여부를 추정하지 않는다. 설계 문서는 결정의 이유를 찾는 참고 자료다.
- 문서와 코드가 다르면 코드·테스트를 기준으로 판단하고 아래 규칙에 따라 문서를 고친다.
- 공급자 실 호출, 유료 smoke, DB 적용, 외부 배포는 별도 요청 범위가 승인한 경우에만 수행한다. 일반 검증은 Fake와 가짜 HTTP 응답을 사용한다.

## 문서 유지 규칙

커밋 전에 이번 변경이 `CODEMAP.md`와 영향받은 지도의 내용과 맞는지 확인한다.

- 고칠 때: 파일·심볼·API(route·DTO·상태 코드)·테이블·컬럼·저장 형식·상태 전이·설정 키·스크립트 옵션·규칙을 추가·이동·삭제·변경했고, 그 대상이 지도에 언급되었거나 `CODEMAP.md` 영역 표의 작업 흐름을 바꿀 때. 단순 서식 변경처럼 문서에 영향이 없는 변경은 문서를 건드리지 않는다.
- 고칠 곳: `CODEMAP.md` 영역 표에서 해당 작업 행의 지도. 맞는 행이 없으면 행을 추가하고, 기존 지도로 담을 수 없을 때만 이 폴더에 새 지도를 만든다.
- 확인 기준: 고친 지도의 "확인 기준" 날짜·revision과 확인한 범위를 갱신한다. 실행하지 않은 테스트·실환경 확인을 확인한 것으로 쓰지 않는다.
- 쓰는 방식: 현재 사실만 쓴다. 경로와 심볼 이름으로 가리키고 줄 번호를 고정하지 않는다. 변경 경위·이력·PR 번호는 커밋 메시지에 둔다. 사라진 경로·심볼은 문서에서 지운다. 같은 사실을 여러 문서에 복제하지 않고 정본 문서로 링크한다.
- 커밋: 문서 수정은 코드 변경과 같은 커밋에 넣는다. 코드를 먼저 커밋하고 문서를 따로 커밋하지 않는다.
- 확인: 문서에 쓴 경로가 존재하고 상대 링크가 깨지지 않았는지 확인한다.
