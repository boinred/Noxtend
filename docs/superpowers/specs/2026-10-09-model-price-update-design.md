# 모델·단가 업데이트와 에이전트 비교 실험 설계

상태: 기본 설계 승인 후 공급자 필터 요구 반영. 구현 계획 작성 단계이며 기능 구현·비교 실행 전

확인 기준: 2026-10-09, 로컬 `main`의 `1c230beab48f7192d5bd39fa576dc227c819d32f`. 코드와 공식 공개 문서를 읽었으며, 계정 키를 사용하는 조회·유료 생성·DB 적용은 수행하지 않았다.

## 목적

새 AI 모델과 가격 변경을 관리자 화면에서 찾아 기존 단가와 비교하고, 사용자가 선택한 변경만 반영한다. 같은 기능을 독립적으로 구현하는 에이전트 실험으로 `xHuman` 참조가 정확성·개발 시간·재작업에 미치는 영향을 관찰한다.

사용자가 선택한 방식은 **버튼으로 최신 정보 수집 → 변경안 확인 → 선택 적용**이다. 이전의 즉시 적용 선택은 후속 선택으로 대체됐다. 대상은 OpenAI·Anthropic·Google의 텍스트·이미지 영역과 Tripo·Meshy의 3D 영역이다. 공급자가 지원하지 않는 조합을 새로 만드는 것은 아니다.

## 범위

- 관리자 단가 화면에 공통 업데이트 흐름을 추가한다. 공급자별 수집·해석은 구분하고 결과 형식과 검토·적용 UI를 공유한다.
- 기존 단가 목록과 수집된 변경안에 공급자 필터를 제공한다. 필터는 수집 대상 선택과 별개이며 조회된 결과의 표시만 바꾼다.
- 신규 모델 발견, 기존 모델의 가격 변경, 가격 미확인, 실행 지원 미확인, 공급자별 조회 실패를 구분한다.
- 공식 API·공개 명세·공식 가격 문서를 수집한다. 여러 공급자의 전체 응답을 하나의 성공/실패로 뭉개지 않는다.
- 출처·수집 시각·요금 조건·적용 시점을 보존하며 기존 단가를 덮어쓰지 않고 새 시행 행을 추가한다.
- 현재 계산기로 표현할 수 있는 요금만 적용한다. 표현할 수 없는 요금도 수집 결과에는 표시하고 적용 불가 이유를 제공한다.
- 모델 발견과 해당 모델의 실행 지원은 별도다. 기존 어댑터가 지원하는 모델은 현재 선택 규칙을 따르고, 미지원 프로토콜·투명 출력·크기·멀티뷰 지원을 이름으로 추정하지 않는다.
- 기존 2D 작업 화면과 진행 컴포넌트는 변경하지 않는다.

제외: 주기적 스케줄러, 무인 자동 적용, 실제 생성으로 호환성 자동 시험, 새 공급자 연동, 모든 과금 체계를 지원하는 계산기 재작성, 과거 호출 일괄 재정산, 구현 결과의 자동 병합·배포.

## 공식 수집 자료와 확인 경계

모델 목록 API가 단가까지 반환한다고 가정하지 않는다. 다음은 현재 확인한 수집 시작점이며, 특정 계정의 권한·응답이나 모든 표의 자동 파싱 성공을 확인했다는 뜻이 아니다.

- Meshy OpenAPI의 모델 enum은 계정별 사용 권한을 보장하지 않는다. `latest`는 고정 모델 버전으로 추측해서 바꾸지 않고, 명시된 버전만 후보 식별자로 사용한다.
- 이번 조사에서는 Tripo의 공개 모델 목록 API와 양사 3D의 완전한 가격 JSON을 확인하지 못했다. 이를 API 부재로 단정하지 않으며 지정 공식 문서 수집을 설계에 포함한다.
- Tripo의 공개 API credit 환산과 기업 계약을 구분한다. [Studio와 API credit 안내](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api)의 서로 다른 credit를 혼합하지 않는다.
- Meshy의 [API 안내](https://www.meshy.ai/api)와 [credit 정책](https://help.meshy.ai/en/articles/9991981-how-do-meshy-credits-work)만으로 모든 계정의 동일 USD/credit를 확정할 수 없다. 구독 요금에서 임의 환산한 값을 공식 단가처럼 적용하지 않는다.
- 가격 수집기는 지정 문서의 표·제목·단위·조건을 함께 검증한다. HTML 구조 변경, 중복되는 등급, 누락 단위, 해석할 수 없는 조건은 `확인 필요`로 남긴다. LLM의 추정값이나 제3자 집계 가격을 공식 값의 대체 경로로 추가하지 않는다.
- 공식 문서의 실제 응답과 구조를 저장한 fixture로 각 수집기를 검증해야 구현 완료다. 링크만 연결하거나 기존 seed를 최신 결과로 반환하는 것으로 수집 성공을 처리하지 않는다.

## 사용자 흐름

1. 단가 화면의 `모델·단가 업데이트` 버튼을 누르고 등록된 공급자 중 조회 대상을 선택한다.
2. 서버가 자격 증명이 필요한 목록과 공개 가격 자료를 수집한다. 명시적인 갱신은 기존 목록 캐시 때문에 과거 결과만 반환하지 않는다.
3. 공급자별 성공·실패·확인 시각과 후보를 표시한다. 일부 공급자가 실패해도 다른 공급자의 결과는 검토할 수 있다.
4. 행마다 모델 ID, 영역, 변경 종류, 기존/수집 단가, 단위와 요금 조건, 출처 링크, 실행 지원 여부, 적용 가능 여부를 보여준다. 변경 없는 행은 별도로 구분한다.
5. 사용자가 적용 가능한 행을 선택하고 적용 시점을 확인한다. 초기 선택은 비어 있으며 변경 없음·가격 미확인·표현 불가 행은 선택할 수 없다.
6. 서버가 검토 당시 값과 현재 DB 상태를 다시 확인한 후 선택 묶음을 적용한다. 결과에 적용·이미 적용·충돌을 구분하고 목록을 다시 조회한다.

조회 실패·정상 빈 목록·미지원 조합·단가 미확인을 다른 상태로 표시한다. 재조회해도 사용자가 보고 있는 변경안이 조용히 교체되지 않으며, 새 수집 결과로 전환할 때 선택을 초기화한다. 공급자 목록에서 사라진 모델은 확인 대상으로 표시하고 기존 단가·설정·작업을 삭제하지 않는다. 확인된 공급자의 기존 단가 모델을 비교 기준으로 삼고, 같은 공급자의 선택한 설정에서 모든 목록 페이지가 정상 수집된 경우에만 합집합과 대조한다. 목록 실패·부분 수집은 누락 판정을 보류한다. 목록 미노출을 모델 폐기나 계정 권한 상실로 단정하지 않는다.

### 공급자 필터

- 옵션은 `전체 / OpenAI / Anthropic / Google / Tripo / Meshy / 미분류`이며 초기값은 `전체`다. 기존 단가 목록과 변경안은 각자의 필터 상태를 가진다.
- 기존 행의 공급자는 저장된 식별 또는 확인된 정확한 모델 매핑으로만 채운다. 이름 접두사로 추정하지 않으며 확인하지 못한 기존 행은 `미분류`와 `전체`에서 보인다.
- 필터 변경은 추가 외부 조회·단가 변경·수집 대상 변경을 일으키지 않는다. 표시 건수와 수집 전체 건수를 구분한다.
- 변경안 필터를 바꾸면 적용 선택을 초기화하고 이를 알린다. `현재 표시된 적용 가능 항목 선택`만 제공하며 숨겨진 행은 적용 요청에 포함하지 않는다.
- 해당 공급자의 결과 없음, 해당 공급자 수집 실패, 정상 수집됐지만 적용 가능 항목 없음은 다른 문구로 표시한다. 공급자별 실패 요약은 필터와 관계없이 확인할 수 있다.
- 라벨이 있는 기존 Select 또는 native select를 사용하고 키보드·포커스를 지원한다. URL 저장·다중 공급자 보기 필터는 이번 범위에 추가하지 않는다.

## 수집 후보와 단가 적용 규칙

### 식별과 출처

- 후보의 식별은 공급자 종류 + 정확한 모델 ID + 영역/작업 + 요금 조건이다. 공급자 설정 ID는 계정별 접근 확인 맥락이며 가격 정책의 공급자 식별과 구분한다.
- 여러 설정에서 같은 후보가 발견되면 설정별 조회 결과를 유지하면서 후보를 중복 제거한다. 단가·공식 시행일이 일치하면 출처·설정 관찰 정보를 합치고 한 번만 적용한다. 같은 후보의 값이 다르거나 다른 조건의 후보가 같은 저장 키를 요구하면 적용을 보류한다.
- 현재 적용 값, 수집 값, USD 또는 credit 단위, 서비스 등급, 크기·품질·텍스처 등의 조건, 공식 시행일의 확인 여부, 출처 URL·확인 시각·자료 해시를 보존한다.
- 공식 시행일 미기재는 수집 시각과 같다고 주장하지 않는다. 제품에서 선택한 적용 시점과 공급자 공표 시점을 구분한다.
- 같은 모델 ID를 서로 다른 공급자·조건이 사용해 기존 단가 키에 충돌하면 자동 병합하지 않고 적용을 보류한다.
- 모델 발견 결과는 검토용이다. 가격 적용이 기존 실행 허용 목록이나 Sprite capability를 우회하는 승인이 되지 않는다. 지원하지 않는 새 계열은 `실행 지원 확인 필요`로 안내한다.

### 가격과 과거 비용

- 기본 대상은 현재 Noxtend의 호출에 해당하는 유료 Standard API 요금이다. 무료·Batch·Priority·캐시 할인·웹 서비스 구독 가격을 대신 적용하지 않는다.
- 단위와 모델의 정확한 매칭을 확인한다. 모델 이름 접두사만으로 다른 변종의 가격을 가져오지 않는다.
- 신규 요금은 새 행으로 추가한다. 기존 행의 수정·삭제 및 과거 시점으로 소급하는 적용은 이 기능에서 제공하지 않는다.
- 기본 적용 시점은 서버가 적용을 확정하는 UTC 시각과 확인된 공식 시행일 중 늦은 시각이다. 공식 시행일이 미래이면 그 이전 적용을 허용하지 않는다. 사용자는 이 하한 이후로 예약할 수 있고, 표시는 사용자의 시간대로 변환한다.
- 새로 수집한 단가 행은 최초 행이어도 시행일 이전 호출에 소급하지 않는다. 기존 수동 등록·seed 행의 레거시 소급 정책은 유지한다. 이 구분을 저장하고 Backend 계산과 Frontend 3D 계산에서 동일하게 해석한다.
- 따라서 기존에 알던 과거 비용뿐 아니라 과거의 `미등록`도 새 단가 등록만으로 바뀌지 않는다. 미확인 가격을 0으로 저장하지 않는다.
- 혼합 입력 단가, 캐시, 여러 컨텍스트 구간처럼 현재 계산기가 표현하지 못하는 요금은 조건을 보존해 표시하고 적용 불가로 남긴다. 단순 평균·높은 단가 선택·임의 정액으로 축약하지 않는다.

### 3D 비용

- Tripo·Meshy는 모델 ID만으로 작업 비용을 결정하지 않는다. 현재 생성 요청의 멀티뷰·텍스처·geometry 등 실제 옵션과 공식 credit 표를 대응시킨다.
- credit/작업과 USD/credit를 다른 값으로 표시한다. USD 환산 근거가 확인되지 않으면 credit 변경은 보여주되 USD 단가 적용은 보류한다.
- 현재 단가와 비용 계산은 계정별 요금제를 구분하지 못한다. Meshy처럼 계정 구매 조건에 종속된 USD 환산은 이번 기능의 전역 단가에 적용하지 않는다. credit 변경과 근거는 수집·비교하고, `계정별 환산 지원 필요`로 USD 적용을 보류한다. 다른 공급자의 적용은 계속할 수 있다.
- 정확히 확인된 고정 작업·옵션의 결과당 USD만 기존 정액 계산으로 반영한다. 옵션에 따라 값이 바뀌어 기존 모델별 정액으로 표현할 수 없으면 적용하지 않는다.
- 이번 기능이 `CreditsConsumed × 단가` 기반 실제 청구 계산을 구현했다고 설명하지 않는다. 결과당 예상 비용과 실제 사용 크레딧을 구분해 표시한다.

## 저장·API·실패 처리 설계

다음은 구현할 책임의 구분이며 아래 새 계약은 아직 존재하지 않는다.

- 수집과 선택 적용을 별도 서버 유스케이스로 둔다. 수집은 운영 모델 설정·적용 단가를 바꾸지 않고 서버에 검토할 후보 snapshot을 저장한다.
- snapshot에는 식별자, 공급자별 결과, 후보 값·출처·기존 값의 비교 기준, 만료 시각을 저장한다. 적용 요청은 request ID, snapshot ID, 선택한 항목, 적용 시점 또는 즉시 적용 선택만 받는다. 클라이언트가 보낸 가격이나 출처를 공식 수집값으로 신뢰하지 않는다.
- 제안 route는 `POST /api/prices/update-previews`와 `POST /api/prices/update-previews/{id}/apply`다. 기존 단가 CRUD와 `{ data, error }` 봉투를 유지한다. 최종 DTO와 오류 코드는 구현 계획에서 양쪽 소비자와 함께 확정한다.
- 검토 유효시간은 30분으로 제안한다. 아직 성공하지 않은 요청의 snapshot 만료·검토 후 현재 단가 변경·다른 적용과의 충돌은 409로 재수집을 안내한다. 만료된 값을 자동 재수집해서 사용자의 선택과 다른 가격으로 저장하지 않는다.
- 선택 묶음의 변경과 적용 결과를 같은 SQL transaction에서 확정한다. request ID로 저장된 성공 결과를 먼저 확인하고, snapshot·선택·적용 시점/즉시 적용 선택이 같은 재전송은 만료 여부와 무관하게 최초 결과를 반환한다. 즉시 적용의 확정 UTC 시각도 최초 결과를 재사용한다. 같은 request ID에 다른 본문을 보내면 충돌로 처리한다. 중간 실패는 선택 묶음을 일부만 저장하지 않는다.
- 기존 `(Model, EffectiveFrom)` unique 제약은 최종 중복 방어로 유지한다. 동시 적용 경합을 일반 500이나 성공으로 숨기지 않는다. 외부 공급자 조회는 DB transaction 밖에서 수행한다.
- snapshot 및 적용 요청 수명과 무관하게 단가 행에 출처·요금 조건·적용 근거를 연결한다. 후보 저장 형식·관련 migration과 기존 행의 기본값은 구현 계획에서 명시한다.
- 자격 증명은 기존 Infrastructure 복호화 경계를 사용한다. snapshot·응답·로그에 키·인증 헤더·전체 외부 오류 본문을 넣지 않는다.
- 서버는 공급자별로 정해진 공식 host·경로만 조회하고 timeout·응답 크기·목록 pagination 상한을 둔다. 클라이언트가 보낸 임의 URL을 조회하지 않는다. 외부 문서 내용은 수집 데이터로만 처리한다.
- 새 일정 실행기·생성 Worker·결제 기능은 추가하지 않는다. 기존 API 호스트와 단가 관리 계층에서 처리한다.

## 검증 및 합격 기준

비교 실험에 앞서 공통 기능 검사를 준비한다. 참가자 자체 테스트 외에 평가자가 동일한 입력으로 검증한다. 공통 HTTP/SQL 검사와 Fake UI 검사의 파일·명령은 구현 계획 Task 1에서 지정하고, 측정 전에 기대 결과·테스트 해시·케이스 수를 고정한다. 네트워크 경계는 저장한 원문 응답으로 대체하되 실제 수집 parser·API·저장 처리는 통과시킨다.

| 사례 | 기대 결과 |
| --- | --- |
| 5개 공급자의 정상 자료 | 영역별 신규/변경/동일 후보와 출처·단위 표시 |
| 목록 pagination·중복 모델 | 모든 수집 페이지 반영, 같은 후보 중복 적용 없음 |

| 완전 목록의 기존 모델 미노출·부분 수집 | 정상 전체 수집만 확인 대상으로 표시, 폐기 단정·기존 데이터 변경 없음 |

| 선택 적용·선택 취소 | 선택된 유효 항목만 저장, 취소 시 단가 변경 없음 |
| 재전송·동시 적용·검토 후 변경·만료 | 중복 없음, 성공한 요청은 만료 후에도 최초 결과 반환, 다른 본문은 충돌 |
| 신규/변경 요금의 시행일 이전·이후 | 이전 추정값과 미등록 유지, 공식 미래 시행일 이전 적용 차단 |
| 새 날짜 버전 단가와 기존 모델 alias | 새 버전의 등록이 유효기간 이전의 기존 매칭·비용을 가리지 않음 |
| 같은 Meshy 모델을 쓰는 서로 다른 계정 | 계정별 환산을 전역 단가로 저장하거나 전파하지 않음 |
| snapshot 가격 변조·미확인 값·유효성 실패 | 서버 검증으로 거부, 묶음의 부분 저장 없음 |
| Frontend 검토 | 로딩/오류/빈 결과, 키보드·포커스, 좁은 화면, 재조회 선택 초기화 확인 |
| 전체·5개 공급자·미분류 필터 | 두 목록의 정확한 표시/건수, 외부 재조회 없음, 공급자 추정 없음 |
| 일부 공급자 실패 후 다른 공급자로 필터 전환 | 실패 요약 유지, 정상 빈 목록·적용 가능 항목 없음과 구분 |
| 변경안 선택 후 공급자 필터 전환 | 선택 초기화 안내, 숨겨진 항목이 적용 요청에 포함되지 않음 |

기능 구현 후 Backend 전체 비유료 회귀와 Frontend unit·lint·typecheck·build·Fake E2E를 실행한다. 정확한 명령과 제약은 [검증 절차](../../../.agents/skills/noxtend-workflow/references/verification.md)를 따른다. Fake·저장 응답 검증을 실제 공급자 조회·가격의 최신성·실제 청구 정확성으로 해석하지 않는다.

## 에이전트 비교 설계

### 이번에 비교할 질문

공통 개발 지침을 유지한 상태에서 **`xHuman`을 참조하는 것이 같은 기능 구현에 도움이 되는가**를 비교한다. 현재 하위 에이전트 도구의 대화 이력 제외만으로 전역·프로젝트 지침 자동 제공까지 배제됐다고 보장할 수 없으므로, 이번 결과를 `지침 없음 대 있음`의 결과라고 부르지 않는다.

### 동일하게 제공할 것

- 같은 기준 커밋에서 만든 독립 작업 사본, 동일 모델·추론 설정·도구·의존성·테스트 환경
- 이 문서의 제품 요구사항과 공통 합격 기준. 아래 진행자용 코드 위치는 참가자 자료에서 제외
- 동일 날짜의 공개 모델·가격 응답 fixture와 source URL·조건 메타데이터. 비밀키나 계정 데이터는 포함하지 않음
- 동일 실행 상한, Subagent-driven 구현·독립 리뷰 방식, 리뷰 피드백 기회와 테스트 명령

고정 fixture로 재현성을 확보하되 실제 수집 기능을 생략하지 않는다. 제품 코드는 지정 공식 URL을 요청하고 parser가 fixture의 원문을 해석하도록 테스트한다. 새 웹 탐색·실 API·유료 호출·다른 참가자 결과 열람은 측정 중 수행하지 않는다. 부족한 외부 정보가 있으면 양쪽에 같은 보충 자료를 제공하고 시점을 기록한다.

### 조건과 역할

| 역할 | 수행 |
| --- | --- |
| A 구현 팀 | 공통 지침 적용, `docs/xHuman` 참조를 실험용 예외로 제외하고 코드에서 탐색 |
| B 구현 팀 | 같은 공통 지침 적용, `docs/xHuman`과 실제 코드를 함께 탐색 |
| 독립 평가자 | 조건명을 가린 코드·실행 결과를 공통 기준으로 검토 |
| 진행자 | 기준 자료·실행 기록·환경 고정, 공통 질문 답변, 결과 비교 |

- 새 비교 에이전트는 대화 기록을 상속하지 않는다. 이번 설계 조사에 참여한 에이전트는 비교 구현에 재사용하지 않는다.
- A의 문서 접근 제한은 도구의 파일시스템 차단을 뜻하지 않는다. 읽기 로그와 자동 제공 맥락을 확인해 문서가 노출된 실행은 오염 여부를 표시한다. 접근 차단을 확인할 수 없으면 완전 격리 실험으로 보고하지 않는다.
- 같은 파일을 두 팀이 수정하지 않도록 사본을 분리한다. 공통 기능 요구사항·공급자 자료의 노출은 동일하게 하고, 한 팀에서 발견한 코드 위치나 해결책을 다른 팀에 전달하지 않는다.
- 최초는 A/B 한 쌍의 예비 비교다. 한 기능의 한 쌍으로 일반적인 생산성 향상률을 주장하지 않는다. 전체 실험 전에 fixture 준비를 마치고 양쪽에 동일한 수치의 시간·사용량 상한을 고정한다. 탐색 과제에서 제안했던 10분 상한은 이번 기능에 그대로 적용하지 않는다.
- Docker 회귀와 E2E 서버는 자원 경합을 피하도록 순차 실행한다. 대기 시간·환경 준비 시간과 에이전트 작업 시간을 나눠 기록한다.
- 공통 합격 기준 충족 여부가 우선이고, 그다음 리뷰 오류·재작업·코드 범위·시간을 비교한다. 토큰·비용은 실제 수집할 수 있을 때만 보고하고 하위 에이전트 사용량도 포함한다.
- 각 팀의 문서 갱신 작업은 코드 구현 시간과 별도로 기록한다. A에 대한 xHuman 읽기·갱신 제외를 명시하고 그 차이를 비교 결과에 남긴다. 제품에 반영할 결과는 이후 실제 코드 지도와 동기화한다.
- 결과 보고에는 성공·실패·상한 초과·미실행을 모두 포함한다. 선택한 구현의 보완·문서 동기화·회귀 확인은 별도 통합 단계이며 자동 merge·push를 하지 않는다.

## 설계 검토 기록 및 구현 상태

- 조사 에이전트는 코드·가격 자료를 읽기 전용으로 확인했다. 이들은 비교 참가자가 아니며 이 설계 조사 시점에는 비교 실험을 실행하지 않았다.
- 독립 설계 리뷰의 계정별 환산 전파·만료 후 재전송·미래 시행일 조기 적용 지적을 반영했다. 변경 없는 행의 적용 제외와 모델 alias의 시행일 회귀 기준도 명시했다.
- 사용자가 기본 설계를 승인하고 구현 계획 작성과 공급자별 필터를 요청했다. 해당 추가 요구를 이 문서와 구현 계획에 함께 반영한다.
- 구현 승인 후 fixture·공통 평가 테스트·신규 API·SQL migration·수집기·UI를 Subagent-driven으로 구현했다. 두 조건의 측정을 종료하고 A를 보완 기준선으로 선택했다. [구현 실행 기록](../plans/2026-10-09-model-price-update.md#실행-기록)과 [비교 결과](../../evals/model-price-update/results.md)가 현재 검증 상태·한계의 정본이다.
