# 2D 재구성 슬라이드 비교·타일 캔버스 맞춤 설계

## 목적

[2D 원본 재구성 비교](2026-10-16-2d-source-reconstruction-design.md)를 실제 작업으로 써 본 사용자가 세 가지를 요청했다.

1. 원본과 재구성을 [MeshBlend](https://meshblend.lervik.com/)처럼 세로 경계를 끌어서 나눠 보고 싶다.
2. 재구성의 바닥 타일 사이에 틈이 있어 이상해 보인다.
3. 담벼락이 바닥 타일로 되어 있고, 건물·나무·가로수가 여러 곳에 나오는데 한 곳에만 놓여 있다.

판단 근거는 지금과 같다. 생성한 에셋 묶음으로 원본 구도를 얼마나 똑같이 다시 만들 수 있는지를 사람이 직접 본다.

## 현재 상태 (2026-10-19 확인)

- 사용자가 본 작업은 로컬 `a9f77a56`이다. 2026-10-15에 V4 분석으로 만들었고, isometric 128×64, 원경 배경 1·타일 3(도로·인도·`masonry_wall_tile`)·오브젝트 6으로 구성된다. 오브젝트 6개 모두 `placements: null`이어서 생성 기준 자리 한 곳에만 그려진다.
- **틈의 원인은 타일 이미지 자체다.** 128×64 캔버스를 가득 채운 다이아몬드라면 알파 128 이상인 픽셀이 50%여야 한다. 실제로는 도로 42%(불투명 상자 115×58), 인도 32%(94×54), 담벼락 26%(84×48)였다. 공급자가 1536×768 요청 캔버스 안에 다이아몬드를 여백을 두고 작게 그렸고, `SkiaImageTranscoder.NormalizeSpriteAsync`는 고정 변환으로 줄인 뒤 캔버스 다이아몬드로 자르기만 한다. 그래서 내보낸 ZIP을 게임에서 깔아도 같은 틈이 생긴다. 재구성 화면은 실제 결함을 정직하게 보여 주고 있다.
- 담벼락 타일과 한 자리 문제는 V4 분석의 결과다. 2026-10-18에 들어간 `AnalyzeSpritesV5`는 서 있는 벽·담장·외벽·지붕·차양을 오브젝트로 분류하고, 오브젝트마다 모든 자리(최대 20)를 돌려주며, 긴 구조물은 반복 구간 하나와 여러 자리로 나누도록 지시한다. 실제 모델이 그렇게 답하는지는 아직 확인하지 않았다(유료 호출 필요).
- 재구성 표시는 `SpritePlanReview.tsx`의 `재구성 투명도` range(기본 50%)로 `SpriteReconstructionLayer` 전체의 투명도만 조절한다. 재구성 층은 `PartsOverlay`의 `underlay`(클릭을 받지 않음)로 원본과 ROI 상자 사이에 깔린다.

## 범위

### 목표

1. **비교/편집 전환**: 투명도 슬라이더를 없앤다. 그 자리에 "비교"·"편집" 모드를 두고, 비교 모드에서는 이미지 위를 끌어 원본(왼쪽)과 재구성(오른쪽)의 경계를 옮긴다.
2. **타일 캔버스 맞춤**: isometric 타일을 새로 생성할 때, 공급자가 그린 그림이 캔버스 다이아몬드를 가득 채우도록 정규화한다. 재구성 화면과 내보내는 ZIP이 함께 고쳐진다.
3. **V5 실제 분석 확인**: 같은 원본으로 V5 분석을 한 번 돌려서 담벼락의 오브젝트 분류와 대표 오브젝트의 여러 자리를 확인한다. 유료 호출이므로 사용자 승인 뒤에 한다.

### 하지 않는 것

- 원본에 보이는 건물·나무를 모양마다 따로 만들지 않는다. 대표 몇 종을 여러 자리에 반복해 놓으면 충분하다(사용자 결정). 에셋 12개 상한은 바꾸지 않는다.
- 재구성 화면에서만 타일을 늘려 틈을 가리지 않는다. 실제보다 더 닮아 보이게 만드는 표시이며, 이전 설계에서 실패 조건으로 정했다.
- 기존 작업의 이미지·역할·자리는 자동으로 바꾸지 않는다. 기존 타일에 맞춤을 반영하려면 사람이 다시 생성한다(유료).
- 정사각(`Square`) 타일, 오브젝트, 원경 배경, 레이어의 정규화는 바꾸지 않는다.
- 모드와 경계 위치는 저장하지 않는다(서버·브라우저 저장소 모두).
- V5 확인 결과에 따른 프롬프트 개정은 이 설계에 넣지 않는다. 결과를 보고 따로 정한다.

### 실패로 보는 것

- 비교 모드의 끌기가 자리 상자를 움직이거나, 편집 모드의 상자 끌기가 경계를 움직이는 것.
- 휴대폰에서 이미지 위의 세로 스크롤이 막히는 것.
- 빠진 에셋이나 표시에 실패한 타일이 비교 화면에서 숨겨지는 것.
- 타일 맞춤 때문에 불투명 타일, 정사각 타일, 오브젝트의 결과가 바뀌는 것.
- 승인 없이 실제 AI를 호출하는 것.

## 설계

### 1. 비교/편집 전환 (Frontend)

**표시 조건**
- 재구성을 보여 주는 조건(`reconstructionVisible(sprite)`)은 바꾸지 않는다. 계획 승인 전에는 지금처럼 ROI 상자만 보인다.
- 모드 버튼("비교"·"편집", `aria-pressed` 버튼 묶음)은 재구성 층이 그려진 상태(`tileFill.status === 'ready'`)에서만 보인다. 계산 중·오류일 때는 버튼 없이 편집 모드처럼 동작하고, 기존 상태 안내·오류·`재구성 다시 계산`을 그대로 보인다. 다시 준비되면 사용자가 마지막에 고른 모드로 돌아간다.
- 처음 모드는 비교, 처음 경계는 50%다. 화면 상태로만 두고 저장하지 않는다.

**비교 모드**
- 재구성 층을 경계 왼쪽에서 잘라(`clip-path: inset(0 0 0 X%)` 등) 오른쪽에만 보인다. 투명도는 없앤다(항상 100%).
- 빠진 에셋의 점선 윤곽과 표시 실패 타일의 윤곽은 같은 SVG에 있으므로 재구성 쪽(경계 오른쪽)에서 보인다. 원본 쪽에는 원본만 보인다.
- ROI 상자·이름표·손잡이는 그리지 않는다. 이미지 전체를 덮는 끌기 면을 `PartsOverlay`의 `children`으로 얹는다. 누른 위치로 경계가 바로 이동하고, 끄는 동안 따라간다.
- `PartsOverlay`에 `parts=[]`를 넘기면 "좌표 정보가 없습니다" 안내가 나오므로 그 방법은 쓰지 않는다. 상자를 숨기는 선택 prop 하나 정도는 추가해도 된다. 3D 화면의 기존 동작은 바꾸지 않는다.
- 끌기 면은 `touch-action: pan-y`로 세로 스크롤을 브라우저에 맡기고 좌우 끌기만 받는다. 세로 스크롤로 넘어가며 `pointercancel`이 오면 경계를 누르기 전 위치로 되돌린다. 스크롤을 시작할 때마다 경계가 튀지 않게 하기 위해서다.
- 경계에는 `role="slider"`, 접근 가능한 이름 `원본·재구성 경계`, 0~100 값, `aria-valuetext`를 둔다. 초점을 받으며 ←/→로 움직인다.
- 이미지 아래쪽 왼쪽에 "원본", 오른쪽에 "재구성" 표시를 둔다. 이 표시는 클릭을 받지 않는다.

**편집 모드**
- 지금의 ROI 선택·이동·크기 조절·키보드 동작을 그대로 쓴다.
- 재구성 층은 마지막 경계 위치에서 잘린 채 남는다. 경계선은 보이지만 끌 수 없고 초점도 받지 않는다.

**전환 규칙**
- 비교 모드로 바꾸면 진행 중인 ROI 끌기를 취소한다(`useSpriteRoiEditor`의 기존 취소 규칙). 선택은 유지한다.
- 대상 카드의 입력(역할·이름·정밀 좌표·자리 추가/삭제 등)은 두 모드에서 모두 동작하고, 재구성은 draft를 따라 다시 그린다.
- 비교 모드에서 카드의 상자 선택 버튼(대상 선택·생성 기준·자리 N)을 누르면 편집 모드로 바뀐다. 선택한 상자를 이미지에서 볼 수 있게 하기 위해서다.

**제거**
- `opacity` 상태, `재구성 투명도` range, `SpriteReconstructionLayer`의 `opacity` prop을 지운다. 관련 E2E(`tests/e2e/sprites-reconstruction.spec.ts`)와 지도([frontend.md](../../xHuman/frontend.md))를 새 동작에 맞춘다.

### 2. 타일 캔버스 맞춤 (Backend)

- 대상은 `SpriteTileLayout.Diamond`(isometric 타일)뿐이다. 새로 생성하거나 다시 생성하는 이미지에만 적용된다.
- `NormalizeSpriteAsync`에서 방향을 적용한 공급자 이미지의 알파 128 이상 픽셀 경계 상자를 구한다. 그 상자를 출력 캔버스 전체에 가로·세로 따로 늘려 그린 뒤, 지금처럼 캔버스 다이아몬드로 자른다. 알파 기준 128은 Frontend 타일 비교(`MIN_ALPHA`)와 같다.
- 거부 판정은 맞춤 전에 지금 규칙으로 한다. 고정 변환으로 배치하고 다이아몬드로 자른 결과에 보이는 픽셀이 없으면 지금처럼 "보이는 픽셀이 없습니다"로 거부한다. 다이아몬드 밖 모서리에만 그린 응답이 맞춤으로 늘어나 통과하지 않게 하기 위해서다(`DiamondMask_RejectsContentEntirelyOutsideCell` 유지). 이 판정을 통과한 이미지만 맞춘다.
- 불투명 이미지와 경계 상자가 이미 이미지 전체인 이미지(기존 Diamond 테스트 입력 포함)는 지금과 결과가 같다.
- 경계 상자의 최소 크기·비율 기준은 두지 않는다. 다이아몬드 안의 작은 그림은 칸 전체로 늘어나고, 떨어진 잡티가 상자를 넓히면 틈이 남는다. 두 경우 모두 기준 검수와 재구성 화면에서 그대로 보인다.
- 고정 변환(`SpriteTransform`) 검증과 투명 요구 검사는 그대로 둔다. 생성 입력·fingerprint·저장 형식은 바뀌지 않는다.
- [공급자와 프롬프트](../../xHuman/providers-and-prompts.md)의 "프레임별 콘텐츠 경계를 자르거나 중심을 다시 계산하지 않는다" 규칙은 Diamond 타일에서만 바뀐다. 루프 프레임도 이미지마다 따로 맞추므로 프레임 사이에 미세한 크기 흔들림이 생길 수 있다. 칸을 빈틈없이 채우는 것을 우선한다. 흔들림이 문제가 되면 기준 이미지의 경계 상자를 루프 프레임에 재사용하는 것으로 바꾼다.

### 3. V5 실제 분석 확인 (유료, 승인 후)

- 구현과 독립적이므로 구현 전후 어느 때든 할 수 있다. 실행 직전에 사용자 승인을 받는다.
- 입력: `a9f77a56`과 같은 업로드(1536×1024), isometric·반복 타일·128px·양쪽 반복, 텍스트 모델 `gpt-5.6-luna`(ChatGPT). 로컬 Docker API에서 새 2D 작업을 만들고 분석만 한 뒤 계획 검수에서 멈춘다.
- 호출 상한: 분석 1회와 그 자동 재시도까지. 이미지 생성은 하지 않는다. 재구성까지 보려면 기준 이미지 생성을 따로 승인받는다.
- 확인 항목: 응답 파싱 성공, 담벼락·담장·외벽이 `object`인지, 원본에 여러 번 나오는 건물·나무·가로수의 `placements`가 2개 이상인지, `placements`가 오브젝트에만 있는지. 의미 품질은 사용자가 계획 검수 화면에서 판단한다.
- 기록: [프롬프트 평가 절차](../../xHuman/prompt-evaluation.md)를 따라 입력·버전·호출 수·확인된 비용·결과·실패를 구현 계획의 실행 기록에 남긴다. `Verdict` 기록과 프롬프트 활성화는 하지 않는다.

## 사용자가 정한 것

- 비교 방식은 시안 C(비교 보기 / 편집 전환)다. 투명도 슬라이더를 이 방식으로 바꾼다.
- 건물·나무·가로수는 대표 몇 종을 여러 자리에 반복해 놓아도 된다.
- 담벼락·자리 문제는 코드 수정보다 V5가 실제로 그렇게 답하는지 먼저 확인한다. 부족하면 그때 프롬프트를 고친다.
- 틈은 생성 후처리에서 에셋 자체를 고친다. 화면에서만 늘리지 않는다.
- 비교 모드의 동작은 위 1절의 플레이백대로 한다. 끌기로 경계 이동, 자리 상자 숨김, 누락·실패 윤곽은 재구성 쪽에 표시, 키보드 ←/→, 휴대폰 세로 스크롤 유지, 편집 모드에서 경계 고정, 처음 모드는 비교, 모드·경계는 저장하지 않음.

## 설계자가 정한 것

다음은 사용자가 따로 확인하지 않은 판단이며 검토 때 바꿀 수 있다.

- 모드 버튼은 재구성 층이 준비됐을 때만 보이고, 계산 중·오류 때는 편집처럼 동작한다.
- 비교 모드에서 카드의 상자 선택 버튼을 누르면 편집 모드로 바뀐다.
- 비교 모드로 바꾸면 진행 중인 ROI 끌기를 취소하고 선택은 유지한다.
- 타일 맞춤은 알파 128 기준 경계 상자를 가로·세로 따로 늘린다. 비율 유지 맞춤은 한 축에 틈이 남아 쓰지 않는다.
- 루프 프레임도 이미지마다 따로 맞춘다.
- 타일 맞춤의 거부 판정은 맞춤 전 지금 규칙으로 하고, 경계 상자의 최소 크기·비율 기준은 두지 않는다.
- 휴대폰에서 세로 스크롤로 넘어가면(`pointercancel`) 경계를 누르기 전 위치로 되돌린다.
- 정사각 타일은 이번에 다루지 않는다. 같은 틈이 확인되면 추가한다.
- V5 확인은 분석만 하고, 이미지 생성은 별도 승인으로 둔다.

## 구현자에게 맡기는 것

- 모드 버튼·경계 손잡이·"원본"/"재구성" 표시의 위치와 모양은 [DESIGN.md](../../../DESIGN.md)와 기존 계획 검수 패턴 안에서 정한다.
- 경계를 자르는 방법(SVG 바깥 래퍼의 `clip-path` 또는 SVG `clipPath`)과 키보드 이동 간격.
- 경계 위치 계산을 순수 함수로 뺄지는 테스트 필요에 따라 정한다.

## 제약

- HTTP 계약·저장 형식·migration 변경이 없다. Frontend 변경은 Frontend 전체 회귀, Backend 변경은 Backend 전체 회귀(유료 smoke 제외)로 검증한다.
- 계층 경계는 [이전 설계](2026-10-16-2d-source-reconstruction-design.md#제약)와 같다.
- 실제 AI 호출, 기존 작업의 재생성, Docker 재배포, push·PR 병합은 사용자가 승인한 범위에서만 한다.
- 지도(`frontend.md`, `providers-and-prompts.md`)는 코드와 같은 커밋에서 고친다.

## 검증

- **Backend 단위** (`SpritePixelTests`):
  - 여백이 있는 Diamond 입력이 캔버스 네 꼭짓점 근처(위·아래·왼쪽·오른쪽 끝 중앙)까지 불투명해진다.
  - 불투명 Diamond 입력과 기존 Diamond 테스트 입력의 결과는 바뀌지 않는다.
  - 알파 128 미만의 흐린 테두리는 경계 상자에 들어가지 않는다.
  - Square 레이아웃의 결과는 바뀌지 않는다.
  - 다이아몬드 밖에만 내용이 있는 입력(`DiamondMask_RejectsContentEntirelyOutsideCell`)과 보이는 픽셀이 없는 입력은 지금처럼 거부된다.
- **Backend 전체 회귀**: 루트 지침의 명령(유료 smoke 제외).
- **Frontend E2E (Fake)**:
  - 계획 승인 전에는 모드 버튼과 경계가 없다.
  - 승인 뒤 처음은 비교 모드이고, 자리 상자가 보이지 않는다.
  - 이미지를 끌면 경계가 이동하고 재구성의 잘린 범위가 바뀐다.
  - 경계에 초점을 둔 ←/→로 값이 바뀌고 `aria-valuetext`가 갱신된다.
  - 편집 모드에서 자리 상자를 끌어 옮길 수 있고 경계는 그대로다.
  - 비교 모드에서 카드의 자리 선택을 누르면 편집 모드로 바뀐다.
  - 누락 에셋 윤곽이 비교 모드에서도 보인다.
  - 390px에서 이미지 위 세로 스크롤이 막히지 않고, `pointercancel` 뒤 경계가 원래 위치로 돌아간다.
  - 1440px·390px, light·dark에서 배치를 확인한다.
- **Frontend 전체 회귀**: 루트 지침의 명령.
- **수동 관찰**: 로컬 화면에서 기존 작업 `a9f77a56`을 조회만 해서 비교/편집 전환을 확인한다. 타일 맞춤의 실제 결과는 유료 재생성이나 3절 확인 뒤 생성을 승인받았을 때 확인한다.
